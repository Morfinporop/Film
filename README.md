# Film — Telegram-бот каталога фильмов

Бот для публикации фильмов из TikTok и подобных источников:

- **Администратор** (ID из `ADMIN_IDS`) загружает видео или баннер (фото), задаёт название и тип показа:
  - **🔗 Ссылка** — кнопка «▶️ Смотреть» ведёт на ваш переходник;
  - **▶️ Видео в боте** — фильм проигрывается прямо в Telegram.
- **Пользователи** видят каталог в виде сетки кнопок (по 2 в ряд) — `/start`.
- **Mini App** — кнопка меню «🎬 Фильмы» открывает каталог-сетку внутри Telegram.
- Входящие обновления приходят через **webhook** на порт **3000**.
- Все данные — в **SQLite** (`/app/data/film.db`), секреты — только в **переменных окружения**.

## Структура проекта

```
src/
  index.js          точка входа: запуск, установка webhook и меню Mini App
  config.js         загрузка и валидация переменных окружения
  db/index.js       SQLite (node:sqlite), репозиторий фильмов
  bot/
    index.js        сборка бота, порядок хендлеров
    user.js         /start, каталог, открытие фильма
    admin.js        /add (мастер), /list, /cancel, управление фильмами
    cards.js        карточки фильмов и сетка кнопок
  web/
    server.js       HTTP: webhook, /app, /api/films, /api/banner/:id, /health
    public/app.html страница Mini App
tests/              unit и интеграционные тесты (без сети)
Dockerfile          образ для хостинга
.env.example        шаблон переменных окружения (без секретов)
```

## Переменные окружения

| Переменная      | Обязательна | По умолчанию        | Описание |
|-----------------|-------------|---------------------|----------|
| `BOT_TOKEN`     | да          | —                   | Токен от @BotFather |
| `ADMIN_IDS`     | да          | —                   | Telegram ID админов через запятую, напр. `7745681987` |
| `PUBLIC_URL`    | да (webhook)| —                   | Публичный HTTPS-адрес без `/` на конце, напр. `https://your-bot.bothost.ru` |
| `BOT_MODE`      | нет         | `webhook`           | `webhook` (хостинг) или `polling` (локальный запуск без HTTPS) |
| `PORT`          | нет         | `3000`              | Порт HTTP-сервера |
| `WEBHOOK_PATH`  | нет         | `/webhook`          | Путь для обновлений Telegram |
| `WEBHOOK_SECRET`| нет         | из `BOT_TOKEN`      | Секрет проверки запросов от Telegram (`A-Za-z0-9_-`) |
| `DB_PATH`       | нет         | `data/film.db`      | Путь к файлу БД. На bothost: `/app/data/film.db` |

Токен и ID никогда не хранятся в коде или Git: они задаются в панели хостинга (или в локальном `.env`, который игнорируется Git).

## Настройка на bothost

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. В панели бота откройте **«Переменные окружения»** и добавьте:
   ```
   BOT_TOKEN=123456:ABC...
   ADMIN_IDS=7745681987
   PUBLIC_URL=https://<ваш-домен-бота>
   BOT_MODE=webhook
   PORT=3000
   DB_PATH=/app/data/film.db
   ```
3. Порт приложения — **3000**.
4. Команда запуска: `npm start` (или сборка из `Dockerfile`).
5. Убедитесь, что папка `/app/data` **постоянная** (volume / персистентное хранилище): иначе база очистится при перезапуске.
6. Запустите бота. В логах должно появиться:
   ```
   [bot] @your_bot инициализирован, режим: webhook
   [bot] webhook установлен: https://<домен>/webhook
   ```
7. Проверка: откройте `https://<домен>/health` — должно быть `ok`.

## Как пользоваться (админ)

| Команда | Действие |
|---------|----------|
| `/add`    | Мастер добавления: видео/баннер → название → тип (ссылка или видео в боте) → ссылка или видеофайл → превью → сохранить |
| `/list`   | Все фильмы: статистика просмотров, кнопки ⏸/▶️ (скрыть/показать) и 🗑 (удалить) |
| `/cancel` | Отменить мастер |
| `/admin`  | Подсказка по командам |

Пользователи: `/start` — каталог. Ссылка `https://t.me/<бот>?start=film_<id>` открывает конкретный фильм сразу.

## Локальный запуск

Требуется Node.js **22.13+**.

```bash
cp .env.example .env        # заполните BOT_TOKEN и ADMIN_IDS
# для локальной разработки без HTTPS:
#   BOT_MODE=polling
npm install
npm test
npm start
```

## Заметки по безопасности

- Webhook защищён заголовком `X-Telegram-Bot-Api-Secret-Token` (секрет из `WEBHOOK_SECRET`).
- Баннеры отдаются через прокси `/api/banner/:id`, поэтому токен бота не попадает в браузер.
- Все команды администратора проверяют `ADMIN_IDS`; для остальных пользователей они не отвечают.
